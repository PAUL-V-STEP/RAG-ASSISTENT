# RAG-ассистент АЛ 3У-М6: обработка запросов

Заготовка комплекта. **Актуальная версия:** [`assistant_api/README.md`](../assistant_api/README.md), схемы PNG — [`docs/diagrams/`](../docs/diagrams/). Ниже сохранён исходный черновик ТЗ (раздел 20).

Все факты о технике в примерах взяты из документа `ТО автолифта АЛ 3У-М6 — версия для RAG V3.txt` (`DATA_FILE`). Параметров, которых нет в документе (давление в МПа, моменты затяжки в Н·м, ТО-2), ассистент не знает и не должен придумывать.

## 1. Назначение

Ассистент отвечает на вопросы по техническому обслуживанию автолифта АЛ 3У-М6. Источник знаний — один текстовый файл (`DATA_FILE`, по умолчанию `ТО автолифта АЛ 3У-М6 — версия для RAG V3.txt`; строк `[вопрос-ответ]` в нём быть не должно, загрузчик это проверяет), разбитый на чанки и проиндексированный в Chroma. Перед поиском вопрос проходит нормализацию: исправление раскладки и регистра, восстановление контекста из истории диалога, приведение к каноническому виду. Часть вопросов закрывается проверенными ответами (уровень Q-A) без генерации.

Каталог `assistant_giga/` к этой ветке не относится и не изменяется. Файл «вопросы и ответы (TXT)» в Chroma не индексируется: он используется только как эталон для оценки.

## 2. Схема обработки запроса

```
вопрос пользователя + история + DialogState
  │
  [0] raw               исходный текст, сохраняется без изменений
  [1] clean_text        Unicode, пробелы, ё→е, единицы, варианты написания ТО
  [2] fix_input         похожие буквы, Caps Lock, латинская раскладка
  │     confirm → «Вы имели в виду…?» → ответ пользователю, конец
  [3] needs_history     нужна ли история (правила, без LLM)
  [4] contextualize     LLM переписывает зависимый вопрос в самостоятельный
  [5] validate_rewrite  проверка переписывания (числа, отрицания, ТО-2, длина)
  │     needs_clarification → уточняющий вопрос, конец
  [6] canonicalize      слоты по глоссарию → canonical, cache_key
  [7] qa_layer          проверенный ответ: direct / hybrid / none
  │     direct → ответ из базы Q-A, переход к [11]
  [8] cache             точный кэш по cache_key → семантический с фильтрами
  │     hit → ответ из кэша, переход к [11]
  [9] retrieval         поиск чанков по standalone
  [10] LLM request      сборка промпта и генерация
  [11] answer           ответ, update_state, история, кэш, лог, трассировка
```

Номер шага (`step_id`) одинаков в коде, логе, трассировке и в этом README.

## 3. Этапы обработки

Для каждого шага указаны вход, выход, влияющие переменные, когда шаг пропускается и что видно в трассировке.

### [0] Исходный ввод

- **Вход:** строка пользователя, история последних реплик, `DialogState` (узел, вид ТО, операция, деталь, ожидающее подтверждение `pending_input_fix`).
- **Выход:** `raw` — сохраняется без изменений до конца обработки, пишется в лог.
- **Трассировка:** строка `[0] raw`.

### [1] clean_text — техническая очистка

- **Что делает:** `NFKC`, обрезка и схлопывание пробелов, ё→е, единые кавычки и тире; единицы («градусов» → `°C`, «минут» → `мин`, «часов» → `ч`, «миллилитров» → `мл`, «литров» → `л`); варианты видов ТО («ТО1», «то-1», «первое ТО» → `ТО-1`; «ежедневное обслуживание» → `ЕО`; «сезонное» → `СО`). Таблица вариантов — в `glossary_extra.yaml`.
- **Регистр** сохраняется; нижний регистр используется только внутри канонизации.
- **Пропуск:** никогда. Выполняется до шага [2] и повторно после него.
- **Пример:** «Как часто   проводится то1?» → «Как часто проводится ТО-1?».

### [2] fix_input — раскладка и регистр

- **Что делает:**
  - `homoglyph` — латинские буквы, похожие на русские, внутри русского слова («TО-1» с латинской T) → кириллица; автоматически;
  - `capslock` — инвертированный регистр («кАК ЧАСТО») или весь текст заглавными → обычный регистр с восстановлением аббревиатур (ЕО, ТО-1, СО, КОМ, АКБ, ГОСТ, ATEGO); автоматически;
  - `layout` — текст набран в латинской раскладке («Rfr xfcnj…») → перевод по раскладке ЙЦУКЕН, включая `[ ] ; ' , . \``, на месте русских букв.
- **Как решается, исправлять ли раскладку.** Для каждого латинского слова (кроме белого списка: Mercedes, Mercedes-Benz, ATEGO, Atego и ручные дополнения) строится русский вариант. Слово распознано, если `pymorphy3` его знает или оно совпадает с термином глоссария или истории. `ratio` = доля распознанных; совпадения с глоссарием и историей добавляют `LAYOUT_CONTEXT_BONUS`.

  | Условие | Действие |
  |---|---|
  | `ratio ≥ LAYOUT_AUTO_MIN_RATIO` (0.8) и (не меньше `LAYOUT_MIN_LATIN_TOKENS` слов или есть совпадение с глоссарием) | `auto` — исправить и продолжить |
  | между `LAYOUT_CONFIRM_MIN_RATIO` (0.5) и автопорогом | `LAYOUT_UNCLEAR_ACTION`: `confirm` — переспросить; `answer_with_note` — ответить с пометкой «Вопрос распознан как…»; `ignore` |
  | ниже 0.5 | не исправлять |

- **Подтверждение.** При `confirm` пользователь получает «Похоже, вопрос набран в латинской раскладке. Вы имели в виду: «…»?». Ответ «да» (в том числе «Lf» в латинской раскладке) запускает обработку сохранённого вопроса, любой другой текст считается новым вопросом.
- **Переменные:** `INPUT_FIX_ENABLED`, `HOMOGLYPH_FIX_ENABLED`, `CAPSLOCK_FIX_ENABLED`, `LAYOUT_*`.
- **Пропуск:** `INPUT_FIX_ENABLED=false`. При выключенной нормализации шаг всё равно работает.
- **Примеры:**

  | Ввод | Результат | Действие |
  |---|---|---|
  | `Rfr xfcnj ghjdjlbncz NJ-1&` | Как часто проводится ТО-1? | auto |
  | `А для CJ?` (в истории ТО-1) | А для СО? | auto (глоссарий) |
  | `кАК ЧАСТО ПРОВОДИТСЯ то-1?` | Как часто проводится ТО-1? | auto, capslock |
  | `Rfr xfcnj ghjdjkbncz NJ-1&` | «Вы имели в виду: Как часто проволится ТО-1?» | confirm |
  | `Как сделать reset ошибки?` | без изменений | none |
  | `Как обслуживается шасси Mercedes ATEGO 1518?` | без изменений | none (белый список) |

- **Трассировка:** вид исправления, `layout_ratio`, список замен «было → стало», нераспознанные слова.

### [3] needs_history — нужна ли история

- **Что делает:** решает без LLM, зависит ли вопрос от предыдущих реплик. Проверки по токенам, первое сработавшее правило:
  1. история пустая → нет;
  2. первый токен — «а», «и», «еще», «тогда», «также» → да;
  3. есть местоимение или указатель («он», «его», «их», «этот», «там», «такой же»…) → да;
  4. нет ни одного предметного термина глоссария (узел, вид ТО, операция, деталь, тема) → да;
  5. иначе → нет.
- **Примеры:** «А для СО?» → да (правило 2); «Их нужно снимать?» → да (правило 3); «Какая периодичность ТО-1?» → нет; «Не меньше скольки минут?» → да (правило 4).
- **Пропуск:** `NORMALIZATION_ENABLED=false`.
- **Если «нет» при непустой истории:** `topic_switch` вычисляется по слотам без LLM (нет общих предметных слотов с состоянием → новая тема).

### [4] contextualize — восстановление контекста

- **Что делает:** LLM (`NORMALIZER_MODEL`, `temperature=0`, строго JSON) получает последние `HISTORY_TURNS` пар реплик (ответы обрезаны до `HISTORY_ANSWER_MAX_CHARS`), `DialogState`, термины глоссария и вопрос; возвращает `standalone`, `depends_on_history`, `topic_switch`, `needs_clarification`, слоты.
- **Главное правило:** в `standalone` переносится объект из истории, но **не ответ** ассистента. После ответа «ТО-1 — через 2 месяца или 250 ч» вопрос «А для СО?» становится «Как часто проводится сезонное обслуживание (СО)?», а не «…через 250 ч?».
- **Ошибки:** таймаут `NORMALIZER_TIMEOUT_S`, невалидный JSON (до `NORMALIZER_RETRIES` повторов) → fallback: `standalone` = текст после [2].
- **Пропуск:** `needs_history=False` или `CONTEXTUALIZATION_ENABLED=false`.
- **Трассировка (`full`):** точный запрос к LLM нормализатора и сырой JSON ответа.

### [5] validate_rewrite — проверка переписывания

- **Отклоняется** (fallback на текст после [2]), если: пропало число из вопроса; пропало отрицание («не», «нельзя», «без», «кроме», «только»); появилось число из ответа ассистента; появился ТО-2 или вид ТО, которого не было; `standalone` длиннее `REWRITE_MAX_RATIO` × исходный; `standalone` похож на ответ.
- **Сверка** — с текстом после шага [2], а не с `raw`: латинский `raw` не содержит русских отрицаний.
- **Уточнение.** Если LLM вернула `needs_clarification=true` (ссылка неоднозначна), пользователю задаётся уточняющий вопрос, шаги [6]–[10] не выполняются, в кэш ничего не пишется.

### [6] canonicalize — канонический вид

- **Что делает:** лемматизация (`pymorphy3`), поиск терминов глоссария по n-граммам, нечёткий поиск (`rapidfuzz`, `FUZZY_CUTOFF`) для длинных слов, аббревиатуры — только точно. Заполняет слоты: `intent`, `node`, `maintenance_level`, `operation`, `part`, `parameter`, `condition`, `period`, `numbers`, отрицание.
- **Intent по правилам** (приоритет над LLM): 0 — предельное значение («сколько… нельзя превышать») → `parameter_value`; 1 — `safety`; 2 — «нужно ли» → `procedure`; 3 — `periodicity`; 4 — `parameter_value`; 5 — `parts`; 6 — `procedure`; иначе `other`.
- **Период:** «два раза в год» → `2/год`, «раз в три года» → `3 год`, «250 часов» → `250 ч`; вопросительные формы («как часто») значения не дают.
- **Выход:** `canonical` — строка из слотов через `|`; `cache_key = sha256(NORMALIZER_VERSION | kb_version | canonical)`.
- **Пример:** «Как часто проводится ТО-1?» и «Через какой интервал делают первое ТО?» → один `canonical` вида `periodicity|-|ТО-1|…` (полный формат — ТЗ-RAG-AL, 11.3).
- **Пропуск:** `CANONICALIZATION_ENABLED=false` (тогда точный кэш работает по хешу сырого вопроса).

### [7] Уровень Q-A — проверенные ответы

- **Что делает:** до поиска применяет стоп-правила (единица, которой нет в документе, например МПа; вид ТО, которого нет, например ТО-2) → `none`. Затем ищет запись базы `QA_BASE_FILE`: точное совпадение `canonical`, затем семантический поиск по `standalone`, проверка слотов (вид ТО, узел, условие, период), отрыв от записи другой группы ответов.
- **Решение:**
  - `direct` — расстояние ≤ `QA_DIRECT_MAX_DISTANCE`, отрыв ≥ `QA_MIN_MARGIN`, intent совпал, запись проверена человеком → ответ из базы без генерации;
  - `hybrid` — расстояние ≤ `QA_HYBRID_MAX_DISTANCE` или запись не проверена (`QA_REQUIRE_VERIFIED=true`) → проверенный ответ идёт в промпт вместе с чанками;
  - `none` — дальше обычный RAG.
- **Режимы** `QA_MODE`: `off`, `shadow` (решение только в логе), `hybrid_only`, `full`. После включения по умолчанию `shadow`.
- **Пропуск:** `QA_LAYER_ENABLED=false`; база устарела (`kb_version` не совпал) — уровень отключается.

### [8] Кэш

- **Точный:** lookup по `cache_key` (`EXACT_CACHE_ENABLED`).
- **Семантический:** поиск по вектору `standalone` с фильтрами `intent`, `node`, `maintenance_level`, `normalizer_version`, `kb_version` (`SEMANTIC_CACHE_FILTERS_ENABLED`), порог **сходства** `SEMANTIC_CACHE_MIN_SIMILARITY` (попадание при сходстве ≥ порога; второй порог текущего кода — `SEMANTIC_CACHE_STRICT_MIN_SIMILARITY`), кандидатов `SEMANTIC_CACHE_TOP_K`, время жизни `SEMANTIC_CACHE_TTL_S`.
- **Не кэшируются:** уточнения и подтверждения раскладки; fallback зависимого вопроса (если `CACHE_STORE_FALLBACK=false`); ответы `direct` и `hybrid`; ответы «в документе нет информации».
- **Трассировка:** ключ, результат, кандидаты со сходством, фильтры, порог.
- **Не путать с Q-A:** пороги кэша — сходство (больше — ближе), пороги Q-A — расстояние (`QA_*_MAX_DISTANCE`, меньше — ближе). Значения между ними не переносятся.

### [9] Ретривер

- Поиск `RETRIEVER_TOP_K` чанков по `standalone` в коллекции `KB_COLLECTION_PREFIX + kb_version`. При выключенной нормализации — по тексту после [2] (или по `raw`, если выключен и шаг [2]).
- **Трассировка:** id чанков и расстояния.

### [10] Сборка промпта и генерация

- **Шаблон:** при всех выключенных флагах — исходный шаблон проекта без изменений; иначе — один шаблон `prompts/generate_extended_ru.txt` с необязательными блоками:

  | Блок | Когда включается |
  |---|---|
  | проверенный ответ и правила работы с ним | решение Q-A `hybrid` |
  | история | нормализация включена и история не пустая |
  | уточнённый вопрос | `standalone` отличается от текста после [2] |

  Так `hybrid` с историей не требует выбора между двумя шаблонами. Пустой блок удаляется вместе с заголовком.
- Модель `LLM_MODEL`, `LLM_TEMPERATURE`, таймаут `LLM_TIMEOUT_S`.
- **Проверка чисел для `hybrid`** (`QA_HYBRID_NUMBER_CHECK`): каждое число с единицей **в ответе модели** должно быть в проверенном ответе, во фрагментах или в самом вопросе. Пример: вопрос про ветер 25 м/с, норма документа — не более 20 м/с; ответ «при 25 м/с нельзя, допускается не более 20 м/с» проходит, выдуманное «30 м/с» — нет. Если проверка не прошла, ответ генерируется заново тем же шаблоном без блока Q-A, в лог пишется `hybrid_number_mismatch`.
- **Трассировка:** точный список `messages`, отправленный в LLM (при `TRACE_SHOW_PROMPT=true`).

### [11] Ответ

- Ответ пользователю; `update_state()` по слотам `canonicalize()`; запись в историю; запись в кэш (если разрешено); строка в `PIPELINE_LOG_FILE`; блок трассировки.

## 4. Сквозные примеры

Значения расстояний и времени — условные; формат вывода — как в режиме `TRACE_MODE=summary`.

**Пример 1. Самостоятельный вопрос.**
```
[0] «Как часто проводится ТО-1?»
[2] без изменений
[3] needs_history=False (история пустая)
[6] periodicity | ТО-1  → cache_key 9c1e…
[7] hybrid (qa002, группа to1_periodicity, запись draft-ai)
[10] промпт: проверенный ответ + 4 чанка + вопрос
[11] «ТО-1 проводится через 2 месяца или через 250 ч работы гидросистемы…»
```

**Пример 2. Эллипсис.** История: «Как часто проводится ТО-1?» → ответ про 2 месяца или 250 ч.
```
[0] «А для СО?»
[3] needs_history=True (правило 2: первый токен «а»)
[4] standalone «Как часто проводится сезонное обслуживание (СО)?»; 250 ч не перенесено
[6] periodicity | СО
[7] hybrid (qa004)
[11] «…два раза в год, весной и осенью…»
```

**Пример 3. Латинская раскладка.**
```
[0] «Crjkmrj Vfujc Eybltv yf 10 k djls&»
[2] layout, ratio 1.00, auto → «Сколько Магос Унидем на 10 л воды?»
[6] parameter_value | numbers=10 л
[7] hybrid (qa017)
[11] «…50 мл Магос Унидем на 10 л…»
```

**Пример 4. Неоднозначная раскладка.**
```
[0] «Rfr xfcnj ghjdjkbncz NJ-1&»
[2] layout, ratio 0.78, confirm; не распознано: «проволится»
    → «Похоже, вопрос набран в латинской раскладке. Вы имели в виду: «Как часто проволится ТО-1?»»
— следующая реплика —
[0] «Lf»  → [2] «Да» → обрабатывается сохранённый вопрос, далее как пример 1
```

**Пример 5. Вопрос вне документа.**
```
[0] «Когда проводится ТО-2?»
[5] validate: ТО-2 в вопросе есть, в standalone не добавлен
[6] maintenance_level обнулён (ТО-2 нет в глоссарии)
[7] none (стоп-правило level_out_of_corpus)
[9] ретривер, [10] генерация
[11] «В документе предусмотрены ЕО, ТО-1 и СО; ТО-2 не описано.»
```

Полный пример блока `full` — ниже, в разделе 5.

## 5. Режим трассировки

Включение: `TRACE_MODE=summary|full`, флаг `--trace`, в консоли `/trace summary`, `/trace full`, `/trace off`, `/trace last`.

Блок выводится в stderr (или в файл `TRACE_FILE`, `TRACE_OUTPUT=file|both`) отдельно от ответа:

```
════════════════ ТРАССИРОВКА ЗАПРОСА #7 ════════════════
[0] raw                 «F lkz CJ crjkmrj dhtvtyb&»
[1] clean_text          без изменений                                       0 мс
[2] fix_input           kinds=[layout], layout_ratio 1.00, action=auto
                        заменено: F→А, lkz→для, CJ→СО, crjkmrj→сколько, dhtvtyb&→времени?
                        → «А для СО сколько времени?»                       1 мс
[3] needs_history       True (правило 2: первый токен «а»)                  0 мс
[4] contextualize       LLM <NORMALIZER_MODEL>, 812 мс, попыток 1
                        → standalone «Какова трудоемкость сезонного обслуживания?»
                        depends_on_history=true, topic_switch=false (llm)
[5] validate_rewrite    ok
[6] canonicalize        intent=parameter_value (правило 4), level=СО, parameter=трудоемкость
                        canonical «parameter_value|-|СО|-|-|трудоемкость|-|-|-|-|-»
[7] qa_layer            кандидаты: qa008 d=0.06 slots_ok · qa007 d=0.11 slots_fail(level)
                        decision=hybrid (запись draft-ai)
[8] cache               exact: miss · semantic: пропущен (hybrid не кэшируется)
```

## 6. Переменные окружения

Все пороги, режимы и пути задаются переменными. Полный список с типами и значениями по умолчанию — в `env.example` (генерируется из `settings.py` скриптом `scripts/gen_env_docs.py`; таблицы этого раздела — тоже).

**Приоритет:** флаг CLI > переменная окружения > файл `ENV_FILE` > `.env` > значение по умолчанию в `settings.py`.

**Профили** `env/*.env`:

| Профиль | Назначение |
|---|---|
| `baseline.env` | базовая линия: нормализация, коррекция ввода и Q-A выключены |
| `normalize.env` | нормализация без Q-A |
| `qa_shadow.env` | нормализация и Q-A в режиме `shadow` |
| `full.env` | всё включено, `QA_MODE=full` |
| `debug.env` | как `full.env` + `TRACE_MODE=full` |

```
ENV_FILE=env/debug.env python -m assistant_api.app
python -m assistant_api.app --print-config          # итоговые значения и источник каждого
```

**Группы:** основное приложение (`APP_MODE`, `DATA_FILE`, `RETRIEVER_TOP_K`, `LLM_*`, `LOG_LEVEL`…); коррекция ввода (`INPUT_FIX_ENABLED`, `LAYOUT_*`…); нормализация (`NORMALIZATION_ENABLED`, `NORMALIZER_*`, `HISTORY_*`…); кэш (`EXACT_CACHE_ENABLED`, `SEMANTIC_CACHE_*`, `CACHE_*`); Q-A (`QA_LAYER_ENABLED`, `QA_MODE`, пороги `QA_*_DISTANCE`, `QA_MIN_MARGIN`…); утилита (`QA_TOOL_*`, `QA_TEST_*`, `QA_CALIBRATE_*`, `QA_MANUAL_*`); трассировка (`TRACE_*`); пакетный прогон (`BATCH_*`).

**Имена порогов:** `*_MIN_SIMILARITY` — сходство, попадание при значении ≥ порога; `*_MAX_DISTANCE` — расстояние, попадание при значении ≤ порога.

## 7. Запуск

### Консоль

```
python -m assistant_api.app [--trace full]
```

| Команда | Действие |
|---|---|
| `/reset` | очистить историю и `DialogState` |
| `/state` | показать `DialogState` |
| `/trace off\|summary\|full` | режим трассировки до конца сессии |
| `/trace last` | повторить блок последнего вопроса |
| `/config` | конфигурация с источниками значений |
| `/qa off\|shadow\|hybrid_only\|full` | режим уровня Q-A до конца сессии |

### Пакетный прогон

```
python -m assistant_api.batch --input batch_example.yaml --stage normalize
python -m assistant_api.batch --input questions.txt --stage full --trace
python -m assistant_api.batch --input batch_example.yaml --profiles env/baseline.env,env/full.env
python -m assistant_api.batch --input batch_example.yaml --compare-with reports/batch/20261106_101500
```

- **Форматы:** `txt` (вопрос на строку, пустая строка — новый диалог, `#` — комментарий), `yaml`, `jsonl`, `csv`.
- **Стадии:** `input_fix` ([0]–[2], без LLM), `normalize` ([0]–[6]), `qa` ([0]–[7]), `retrieve` ([0]–[9]), `full` ([0]–[11]).
- **История:** `fixed` — в историю пишется эталонный ответ `a:` из файла; `live` — фактический ответ.
- **Отчёты** `reports/batch/<дата_время>/`: `results.jsonl`, `summary.md`, `traces.jsonl`, `traces.md`, `config.json`.
- **Код выхода:** 0 — успех; 1 — доля пройденных ниже `BATCH_FAIL_UNDER`; 2 — ошибка входного файла.

### Утилита qa_tool

```
qa_tool validate                       # проверка базы, ошибки 1–12
qa_tool build [--rebuild]              # сборка индекса Q-A
qa_tool list | show qa017
qa_tool verify qa017 --by "Фамилия"    # пометить запись проверенной
qa_tool ask "Сколько Унидема на 10 литров?" --trace
qa_tool manual                          # ручная проверка в REPL
qa_tool test [--type match]             # автотесты qa_tests.yaml
qa_tool calibrate                       # подбор порогов
qa_tool stats | clear | export --format md | config
```

Каждый флаг утилиты имеет переменную окружения (`QA_TOOL_*`, `QA_TEST_*`, `QA_CALIBRATE_*`).

## 8. Кэш

- Индекс — `CACHE_INDEX_PREFIX` + `kb_version`: записи старой базы (`docs.txt`) не возвращаются. Очистка старого индекса: `‹этап 0: команда›`.
- Подбор порога: `python scripts/eval_cache_threshold.py` — ложные попадания и промахи на контрастных парах и группах перефразировок, с фильтрами и без; отчёт в `reports/`.
- Полное отключение: `EXACT_CACHE_ENABLED=false SEMANTIC_CACHE_ENABLED=false` (удобно для пакетных прогонов).

## 9. Уровень Q-A

- **Добавление записи:** правка `qa_base.yaml` → `qa_tool validate` → `build` → `test`. Перефразировки не копируются из `qa_tests.yaml`.
- **Проверка человеком:** `qa_tool verify <id>`; до этого запись даёт максимум `hybrid`.
- **Калибровка:** `qa_tool calibrate` на 70 % тестов, проверка на оставшихся; итоги — в `reports/qa/`.
- **Переход `shadow` → `full`:** после прохождения критериев приёмки и просмотра лога `shadow` на реальных вопросах.
- **Устаревание:** при изменении `DATA_FILE` меняется `kb_version`, уровень отключается до `qa_tool build`.

## 10. Глоссарий, белый список и версии

- `glossary_canonical.yaml` собирается `scripts/build_canonical_glossary.py` из строк `[глоссарий]` документа; ручные дополнения — `glossary_extra.yaml` (только термины из документа).
- Белый список латиницы (`LAYOUT_LATIN_WHITELIST_FILE`) собирается из латинских слов документа (Mercedes-Benz, ATEGO, Atego) плюс ручные дополнения.
- `NORMALIZER_VERSION` повышается при любом изменении промптов, правил, глоссария или белого списка: это обновляет ключи кэша.
